# X4 Pro 性能候选版 0.4.2-perf.1

设备版本：`1.6.5-integrated.0.4.2-perf.1`。这是从 0.4.1 完整源码归档建立的独立副本，保留其中文断行、TTF 缓存和单击电源修复。源码未提交、未推送。安装状态见交付目录 `deployment.json`。

## 实施与证据

原 `TxtReaderActivity.cpp` 第 257–282 行在每次重绘时重新读正文和排版，并保存索引、进度；第 534–565 行即使索引不变也打开文件并两次 flush。改为复用当前页排版、对已成功保存的进度和索引去重，索引内容不变时不打开文件。新页仍先保存有效索引，再原子保存进度，保留已有突然掉电时的恢复粒度。失败不会标记已保存，下次重绘重试。索引头改为检查完整 30 字节写入；文件格式仍为 v4，兼容现有 v3/v4 缓存，无需清理阅读进度。

`Txt.cpp::readContent` 原来每次打开正文并读取 8 KB，大量相邻页重复读取重叠内容。增加每个已加载 TXT 独享的 16 KB PSRAM 预读窗口。首次请求仍仅读需要的 8 KB，后续缺失才预读；缓存命中无需打开正文。缓存只存字节，不持有额外文件句柄，不绕过 HalStorage 锁。无 PSRAM/分配失败时直接读取，退出销毁释放；短读不被标记为有效缓存。正文在阅读期间由本地文件系统独占，USB Drive 仍采用原有重启与独占协议。

左对齐/现有两端对齐路径不再计算未使用的行宽；居中、右对齐、RTL 转右对齐仍测宽。恢复时索引偏移改为每批最多 32 项（128 字节栈缓冲）读取，仍校验首项、递增、文件边界及短读。没有更改字形、屏幕波形、灰阶、刷新频率或翻页输入规则。

## 与 0.4.1 的同条件主机对比

原始《水浒传.txt》2,498,639 字节，生产 TXT Reader、同一模拟 HAL/字体度量、前 120 页。对比基线直接取自 0.4.1 归档，日志附于交付目录。

| 指标 | 0.4.1 | 本候选 |
|---|---:|---:|
| TXT 正文读取次数 | 120 | 33 |
| TXT 正文读取字节 | 983,040 | 532,480 |
| 每页最多测宽调用 | 417 | 357 |
| 每页最多累计测量码点 | 11,920 | 9,640 |
| 同页重绘 50 次：正文读取 | 50 | 0 |
| 同页重绘 50 次：索引写入 / flush | 50 / 100 | 0 / 0 |
| 同页重绘 50 次：进度保存 | 50 | 0 |

读取次数减少 72.5%，读取字节减少约 45.8%。这不是设备提速百分比。字体度量、SD 控制器、ESP32-S3 和墨水屏延迟在主机测试中没有被模拟为真实硬件耗时。用户此前的 >5 秒开书、>10 秒翻页属于 0.4.0；0.4.1 和本候选均没有已确认的安装后耗时记录。

## 阶段计时与定位范围

`lib/Performance` 使用固定 16 个原子计数器（共 256 字节静态 RAM），记录 count/total_ms/max_ms/last_ms。热路径仅读 millis 和更新内存，不写 SD、不逐页打印串口。在退出阅读或天气（包括从其上层菜单进入休眠）时，导出 `/.crosspoint/performance-last.csv`。文件无书名、Wi-Fi、坐标或凭据；短写时保留旧报告。FAT 的 remove+rename 并非掉电原子，极端掉电可丢此诊断文件，不影响原书文件。边界导出自身有一次约 1 KB 的写卡成本，未计入 activity_exit。

| 字段 | 用途与边界 |
|---|---|
| boot_setup / font_init / font_ensure | 开机或深睡唤醒的软件初始化；不含 ROM/引导加载器，不等于唤醒到屏幕稳定 |
| activity_enter / activity_exit | 应用进入、退出；聚合各类应用，测量单个场景前可重启 |
| navigation_lock_wait / render_lock_wait | 导航和渲染任务拿锁的等待；不含全部触摸采样延迟 |
| reader_frame_inclusive / txt_layout / txt_persist | 阅读帧总工作（含面板调用）、当前页排版、索引/进度保存；长跳页补索引工作在阅读帧内 |
| panel_bw_call / panel_gray_call / panel_wait | 屏幕驱动函数调用时间，包含软件传输和部分等待；异步面板等待单列，不能直接当作纯物理波形时间 |
| shelf_stop_wait / shelf_cover | 书架退出等待和封面工作 |
| weather_poll | HTTPS 状态机每次调用占用时间，便于发现同步阻塞阶段 |

计数自本次启动累计，深睡后重新开始；嵌套阶段不要直接相加。total_ms 为 uint32，长期累计可回绕；计数器单项原子读取，跨线程整张报告不是同一时刻的事务快照。实际点击到画面稳定仍应录像/秒表记录。

核查后的剩余热点：
- `DesktopShelf::stop` 等待 coverBusy；EPUB 元数据解析、解压和图像解码开始后仍没有端到端取消。这次保留所有权等待，未强杀可能持有 SD 资源的任务。
- ActivityManager 仍以单帧缓冲渲染锁保证生命周期；阅读翻页可能等待当前屏幕刷新。未丢弃或合并输入来制造响应变快的表象；现有输入缓存容量仍有边界，快速连点需要实机验证。
- 天气保留 IDF 异步 HTTPS 客户端，但 DNS/连接/清理等单次调用仍可能阻塞。缓存、定时深睡、低电量保护和阅读恢复逻辑未更改。
- EPUB 排版、应用网络请求、睡眠硬件初始化本次没有未经测量的行为优化；已有字体缓存修复保留。没有常开 Wi-Fi、关闭深睡、永久最高频或常亮前光。

## SD 安装及实机验收

仅使用交付目录的 `x4pro-integrated-0.4.2-perf.1-candidate.bin` application 镜像。保留上一已知可用 application；不使用 factory 镜像，不擦写分区，不删除 `.crosspoint`。核对实际连接的 X4 Pro、当前 About 版本后，将文件复制到 SD 的 `CrossPoint-Install/`，回读核验 SHA256 并安全卸载。保持 USB 供电，退出 USB Drive，从设置 → 系统 → 从存储卡更新固件选择该文件，由用户在设备菜单执行更新。

安装后核对完整版本，记录触摸和实体键分别的开书、重开、连续 10 页、返回/菜单、应用启动、天气缓存页/在线刷新、单击休眠/唤醒时间；快速重复点击时核对实际页码和是否漏输入。打开并退出一次阅读后，连接 USB Drive 取回 `/.crosspoint/performance-last.csv`。每个独立场景可先重启再测，避免累计统计混淆。另需检查中文 TXT/EPUB、书签/进度、六格书架、八入口、三个游戏存档、触摸/实体键/前光、天气定位/深睡更新/阅读恢复及续航。候选构建通过不等于设备验收通过。
