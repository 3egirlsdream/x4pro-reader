## 主机性能与内存

机器：Apple M5，32 GiB RAM，arm64 Darwin；Apple Clang 17.0.0，C++20，`-O2 -fsanitize=undefined`。
固定中盘样本重复搜索 200 次，计时包括逐工作单元读取主机单调时钟的开销；代码与数据已预热。
最终独立采样：平均 208.21 µs，最大 271.33 µs，最大单步观测 28.00 µs；最多 2925 工作单元。
这些数字不包含墨水屏、SD 卡、字体加载，不能作为 ESP32-S3 速度承诺；主机调度也会影响极值。

`/usr/bin/time -l build/game-tests/game-tests` 实测整个模型测试进程最大 RSS 为 3,751,936 字节，报告 peak memory footprint 为 3,047,808 字节。
这是包含测试/标准库/UBSan 的主机进程占用，不是游戏在设备上的堆用量。

| 类型 | 字节 | 证据性质 |
| --- | ---: | --- |
| Game2048 | 24 | 主机 sizeof 与 Xtensa ELF 类型布局相同 |
| Gomoku | 230 | 同上 |
| GomokuAI | 404 | 同上；含搜索工作棋盘、12 个候选与 29 字节邻域位图 |
| Game2048Activity | 932 | Xtensa ELF DWARF 的 `DW_AT_byte_size`，含基类/存档缓冲 |
| GomokuActivity | 1552 | Xtensa ELF DWARF 类型布局，含 AI/棋盘/基类/存档缓冲 |

Activity 为一次申请的拥有期对象。循环没有游戏专用堆分配，模型不递归；存档用短期 JSON 内存与五子棋验证 scratch（470 字节有效成员），沿用 AppStorage 的路径 scratch。
上述类型大小不包含已有字体缓存、帧缓冲、FreeRTOS 栈、存储组件开销。固件静态 RAM 为 102,728 字节，与导入天气版相同；未测设备运行时堆峰值或高水位。

## 最终固件

- 环境：`x4pro-gh_release`；ESP32-S3、16 MB Flash、DIO/80 MHz；FreeInk SDK 固定 `111fdcc7f0176c3ee38391a160ee296bf492dbd8`。
- 版本字符串：`1.6.5-weather.0.2.0-games.0.1.0`。
- 链接 Flash：5,905,570 字节，比天气 0.2.0 清单 5,893,242 增加 12,328 字节。
- 最终应用 BIN：5,910,592 字节；原应用分区 6,553,600 字节，文件仍有 643,008 字节余量。
- 编译静态 RAM：102,728 字节。esptool 镜像检查识别 ESP32-S3，校验和及验证哈希均有效。
- 没有重新读取设备分区表；这里验证的是源码分区布局和构建文件尺寸。没有自动刷机，没有提交/推送 Git。

原始日志、镜像元数据、校验和与补丁在上级 `firmware/`；最终构建日志来自本独立源码目录。

## 待实机验收

1. 安装由用户按原天气版更新流程手动执行。打开两个应用，确认中文字体、竖屏布局和返回应用菜单；先在不同方向进入再退出，检查恢复方向。
2. 2048 实测四向触摸、侧键轴切换、连续合并、无效移动不刷屏、达到 2048 后继续、新局及退出重开恢复。
3. 五子棋实测边缘/角点命中、选点反馈、两次触摸落子、侧键选点与确认、先后手、终局和新局。
4. 记录 `GAME AI nodes=... compute_us=...` 与从用户落子至 AI 落子的完整墙钟；检查思考中返回、Home、菜单和长按电源休眠是否能及时取消。
5. 连续进入/退出每款应用各 50 次，对比 `Heap enter/exit free/max`，排除持续下降；这些日志在销毁对象前输出，应比较同一生命周期阶段，并另测系统空闲堆。
6. 实测全刷/快刷残影及高频触摸响应，检查前光面板打开/关闭后的棋盘恢复；记录单局/24 小时耗电。
7. 游戏中执行普通休眠、天气休眠、定时天气更新与唤醒回首页，再开游戏确认棋盘；同时复测阅读进度和长篇 TXT。

以上硬件项均未在本会话执行。主机取消/生命周期测试不替代真实 ESP32、SD、电源和墨水屏联调。
